# Recipes Service Contract

This repository owns the WordPress app artifact consumed by `mae-storm-infra`.
The infra repo owns the VM, reverse proxy, secrets, volumes, backups, and
deployment orchestration.

## Artifact

- Build command: `just build-artifact version=<git-sha-or-release>`
- Output: `dist/recipes-<version>.tar.gz`
- Contents: tracked application source, plugin/theme assets, Composer/Yarn
  manifests, local smoke scripts, and service contract docs.
- Exclusions: local WordPress state, uploads, database files, dependency caches,
  OpenTofu state, and secrets.

## Runtime

- Public hostname: `recipes.maestorm.com`
- Container health path: `/wp-json/`
- Required WordPress plugin: `mae-storm-recipes`
- Required WordPress theme: `mae-storm-recipes`
- Required Composer dependency: Timber
- Required PHP: 8.3+
- Required WordPress: 6.5+

The plugin owns the recipe model, import/review workflows, private access gate,
and REST protection. The theme owns Timber templates and frontend assets. The
theme also provides plugin-facing Timber templates such as the private login
screen.

## Environment And Secrets

- `MAE_STORM_RECIPES_SHARED_PASSWORD`: shared frontend gate password.
- WordPress database credentials are owned by infra and injected into
  `wp-config.php` or container environment.
- WordPress salts are owned by infra and must not be committed here.

## Persistent Data

- MariaDB database.
- `wp-content/uploads`.
- Candidate source artifacts and uploaded recipe images.
- Runtime WordPress config generated by infra.

## Backup And Restore

Infra backups must include:

- MariaDB dump.
- `wp-content/uploads`.
- Candidate source artifacts and uploaded recipe images.
- Runtime config needed to recreate WordPress.
- App artifact identifier and infra git SHA.

App-side restore smoke checks should activate the plugin/theme, confirm the
private access gate is active, and render a private recipe view from restored
data.
